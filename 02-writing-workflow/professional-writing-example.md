# Professional Writing Example

This example demonstrates a professional writing workflow for a Business Analyst: **Draft, Verify, Refine, and Human Sign-off**.

**Scenario:** Prepare a short requirements summary for stakeholders following a discussion about improving an employee service request process.

## 1. AI-Generated Draft

### Requirements Summary

The team discussed improving the current employee service request process. Employees currently submit requests by email, which makes it difficult to track their requests. The operations team suggested introducing a central portal where employees can submit requests and check their status.

The new solution should make the process easier for employees and help the operations team manage requests more effectively. Security should also be considered because some requests may contain sensitive employee information.

**Next steps:**
- Review the current process.
- Define the main requirements for the proposed portal.
- Identify security requirements.
- Discuss the proposed solution with stakeholders.


## 2. Fact Verification

I checked the draft against the source information:

| Item | Verification Result |
|---|---|
| Employees currently submit requests by email | Confirmed |
| Employees have difficulty tracking requests | Confirmed |
| A central portal was suggested | Confirmed |
| Employees should be able to check request status | Confirmed |
| Some requests contain sensitive information | Confirmed |
| The portal will definitely replace email | Not confirmed; removed |
| The solution will make the process more effective | Not confirmed as an outcome; reworded |
| Specific security requirements | Not provided; marked for clarification |


## 3. Tone Refinement

I improved the document by:

- using clear and neutral Business Analyst language;
- separating confirmed information from assumptions;
- avoiding language that presents a proposed solution as already approved;
- making the next steps specific and easy to understand;
- keeping the summary concise for a stakeholder audience.


## 4. Human Review and Sign-off

I confirmed that the final version:

- confirmed stakeholder information is represented accurately;
- proposed ideas are not presented as final decisions;
- missing security details are clearly identified;
- no sensitive or real business information is included


## 5. Final Version

### Employee Service Request Process - Requirements Summary

The current employee service request process relies on email submissions. Stakeholders identified difficulty in tracking request status and discussed the possibility of introducing a central portal for submitting and tracking requests.

### Confirmed Requirements

- Employees should have a central location to submit service requests.
- Employees should be able to view the status of their requests.
- The process should support requests that may contain sensitive employee information.

### Points Requiring Clarification

- Which types of service requests should be supported?
- What request statuses should be visible to employees?
- What security and access-control requirements apply to sensitive requests?

### Proposed Next Steps

1. Document the current service request process.
2. Gather detailed requirements from relevant stakeholders.
3. Define the required security and access controls.
4. Review the proposed requirements with stakeholders before solution design.
